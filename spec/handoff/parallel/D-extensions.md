## 1. 目的

## 2. 作るもの

### 2.1 ソースの種類（`source/`）

既存の Sample、Stream、Callback、UserBuffer と同じ内部 IF（`source_if`）で作る。

- **Oscillator**
  - 波形: 正弦、矩形、三角、ノコギリ
  - 帯域制限をする（エイリアシングを抑える）
  - 周波数とデューティを、Parameter で動かせる
- **Noise**
  - 白、ピンク、ブラウン
  - 決定論のため、シードを固定する（2.5）
- **Granular**
  - 素材: Sample の波形
  - グレインの長さ、密度、位置、ばらつき、窓、ピッチ
  - 固定容量のグレインのプールで動かす
- **Patch**
  - 波形生成パッチ（設計書 5 章、11.1 のパッチエディタの対象）
  - ノードのグラフを、ビルドの時点で決まった順に評価する
  - パッチの形式は buildtool の対象になる。buildtool は C の持ち場なので、形式の定義を `requests/D-*.md` に書き、C と統合担当に渡す
  - テストでは、パッチを API かテストの中で組み立てる
- **Input**
  - 入力デバイスの音を、ボイスとして鳴らす
  - platform に入力デバイスが要る場合は、platform が持ち場の外なので依頼に書く
  - それまでは、ゲームが渡す入力の口（ManualOutputDevice と同じ考え方）で作る
- 5.1 の実行方式と 5.2 の約束を守る
  - 低遅延と先行描画
  - RT で安全であること
  - 初期化のあとに確保しないこと
- 公開 API が要るものは、`snd_play_*` の新しい関数として足す（共通の決まり 4 章の範囲で）。決定番号で記録する。

### 2.2 dsp の新しいファイル

- **タイムストレッチ**: ピッチを変えずに再生速度を変える（WSOLA か位相ボコーダ。どちらにするかは決定番号で記録する）。Sample と Stream のボイスで使えるようにする
  - ボイス側の配線が core に及ぶ場合は、B の持ち場なので依頼に書く
- **コンボリューション**
  - 分割畳み込み（uniform か non-uniform partitioned）
  - IR は事前に周波数領域へ変換しておく
  - DSP プールの枠で動かす
  - FFT は自前で用意する（サードパーティの依存は禁止）
- SIMD の構成（`SND_SIMD_SCALAR=ON`、`-mavx2 -mfma`）で、スカラーと結果が許容差の中で一致すること

## 3. テスト

解析的に期待値が分かる検査にする。

- **Oscillator**
  - 周波数と振幅を DFT で確かめる
  - 帯域制限の効果（ナイキストより上の成分の量）
- **Noise**
  - スペクトルの傾き（白 0、ピンク -3 dB/oct、ブラウン -6 dB/oct）を、許容差の中で確かめる
  - 同じシードなら、ビットが一致する
- **Granular**
  - 密度とグレイン数の関係
  - 窓の和
  - 位置の範囲
- **Patch**
  - 小さなグラフ（オシレーター → ゲイン → 出力）で、期待どおりの波形になる
  - 評価順が決定的である
- **タイムストレッチ**
  - 速度 ×0.5 / ×2 で、長さが期待どおりになる
  - 主な周波数が変わらない
- **コンボリューション**
  - インパルスの IR で、出力が入力と一致する
  - 既知の短い IR で、直接の畳み込みと許容差の中で一致する
  - 遅延が仕様どおりである
- **RT 安全性と負荷**
  - 各ソースを上限の本数で鳴らす
  - 初期化のあとの確保がゼロ
  - 処理時間を報告に書く
- 7 章の表で D の範囲にある行（動的生成・入力、ピッチ・速度の行のタイムストレッチ）に、テストを対応させる
