## 2. 作るもの（9 章の全部）

### 2.1 公開 API

`physics/include/snd/physics/` に置く。C++ と、C の両方を用意する。C は `snd_physics_*` の名前で、`sonus.h` と同じ流儀（ハンドル、`snd_result`、`struct_size`）にする。

- `PhysicsAudio` の生成と破棄。設定には次を含める。
  - 予算: 毎秒の件数。既定は 300（仮）。
  - 格子の大きさ
  - クールダウンの時間
  - 追跡表とクールダウン表の容量（固定）
  - 継続する接触のタイムアウトとフェード
- `SubmitContacts(PhysicsAudio*, const Contact*, uint32_t, float dtSeconds)`
- `PlayFootstep(PhysicsAudio*, EmitterHandle foot, uint16_t footMaterial, const SurfaceWeight*, uint32_t, Motion)`
- `PlayAt(event, position)`
- マテリアルの対応表と、組の上書き表の登録と差し替え。ゲームの物理マテリアルを、サウンドマテリアルに写す。
- 統計: 捨てた数（理由ごと）、まとめた数、予算で落とした数、追い出した数、代替が起きた数（理由ごと）。

### 2.2 動作

- **間引き（9.4）**: 1 回の SoA のパスで、次の順に処理する。
  1. 閾値で捨てる。
  2. 格子とマテリアルの組でまとめる。衝撃量は最大を取り、個数は Parameter で渡す。
  3. クールダウンで捨てる。
  4. 衝撃量で並べ、予算までを再生する。
- **鳴らす音の決め方（9.3）**
  - 代替の順は、組の上書き → 両方の材質の既定を重ねる → 全体の既定。組の表は `table[min*N+max]` の 1 回の参照で引く。
  - 強さは、カーブで次のように写す。
    - 衝撃量 → ベロシティのレイヤーと音量
    - 質量 → ピッチ
    - 相対速度 → 擦れ音の音量とピッチ
- **表面パラメータ（9.1）**: 「濡れ」などは、Event の Parameter として渡す。
- **足音（9.2）**: 重みの大きい 2 つまでを鳴らし、重みを音量に写す。
- **継続する接触（9.5）**: Slide と Roll は、物体ペアのキーで追跡する。
  - 最初の報告で鳴らし始める。
  - その後は速度の Parameter を更新する。
  - 報告が途切れたら、フェードアウトして止める。
  - 表が溢れたら、いちばん古いものから追い出す。
- **Break** の扱いを決めて実装する。決めたことは決定番号で記録する。
- 初期化の後に、メモリを確保しない（固定容量）。

### 2.3 データ

マテリアル表と強さのカーブの置き場所を決める。

- ゲームが API で渡すか、バンクに入れるかを決める。
- バンクに入れる場合は、バンク形式（`bank/`、`buildtool/`）の変更になる。どちらも A の持ち場の外なので、`requests/A-*.md` に依頼を書く。
- それまでは、API で渡す形を完成させる。

## 3. テスト

`physics/test/` に置く。期待値を解析的に出せる検査にする。

- 間引きの各段を、件数で厳密に確かめる。
  - 閾値ちょうど
  - 格子の境界
  - クールダウンの境界
  - 予算と dt の換算
- 負荷とバースト（14 章）
  - 1 フレームに接触 1000 件
  - 4 倍の要求
  - 初期化の後に確保がゼロであること（数えるアロケータを使う）
- 代替の順と、それぞれの統計
- 足音の重み → 音量
- 継続する接触
  - 開始
  - 更新
  - タイムアウトの後のフェード
  - 追い出し
- 本物の再生は、C API の系で確かめる。
  - 出力は `SND_OUTPUT_MANUAL` と `snd_advance_output`
  - 音は user buffer かバンク
- 7 章の機能カバレッジの表に physics の行は無いが、9 章の各節を、それぞれ 1 本以上のテストで確かめる。
