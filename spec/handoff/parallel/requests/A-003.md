# A-003: 代替（フォールバック）の一覧をツールで見る（tool への依頼）

- 依頼元: セッション A（physics）
- 宛先: tool / livelink（セッション C）
- 状態: 未着手

## 1. 背景

設計書 9.3「代替が起きたことはツールで一覧できる」。physics はゲームスレッドで、観測コールバック
（`snd_physics_config.observer`、`snd_physics_set_observer`）に 1 件ずつ記録（`snd_physics_record`）を渡す:

- `kind`: PLAY / START / UPDATE / STOP / FALLBACK
- `stage`: PAIR / SINGLE / DEFAULT / NOTHING / FOOT_MOTION / FOOT_ANY / FOOT_DEFAULT / DIRECT
- `flags`: POSITION_ONLY（Emitter が無く `snd_play_at` で鳴らした）、UNKNOWN_MATERIAL、RESTART
- Event、接触種別（足音はモーション）、サウンドマテリアルとゲームの物理マテリアル（A, B）、衝撃量、ベロシティ、
  相対速度、質量、音量、ピッチ、個数、位置、物体 ID、ハンドル、記録した Parameter（ID と値）、API の結果

累積の統計は `snd_physics_get_stats`（`snd_physics_stats`）。

physics は公開 API だけを使う上位層なので、ライブリンク（core に依存）には直接は送れない。

## 2. 依頼

1. ライブリンクに「アプリケーションの記録」を運ぶメッセージ（ゲームが任意のバイト列と種別 fourcc を送る）を足す、
   またはゲーム側のライブリンク送信に physics の記録を載せる口を用意する（physics からは関数ポインタで呼べる形）。
   種別は `'PHYR'`（`snd_physics_record` の固定長部分 + Parameter の配列）と `'PHYS'`（`snd_physics_stats`）を想定。
2. ツールの画面:
   - 代替の一覧: FALLBACK 記録を (材質 A, 材質 B, 接触種別, stage) で集計し、件数・最後に起きた時刻・Event を表に出す。
     UNKNOWN_MATERIAL はゲームの物理マテリアル番号ごと（対応表の抜けを見つけるため）。
   - 統計: 間引きの各段で捨てた数、予算で落とした数、追い出し、POSITION_ONLY の数。
   - 追跡中の擦れ・転がり: START / UPDATE / STOP から、いま鳴っているものと最後の速度・音量。
3. 記録の再生（11.3）に入れるかどうかは C の判断に任せる。

## 3. physics 側の対応

送信の口が決まったら、physics の設定に送信先（関数ポインタと user）を足すか、ゲームが観測コールバックから自分で送る例を
ヘッダに書く。
