# B-1: ライブリンクの規則表に variant を足す（宛先: セッション C / livelink）

- 出した側: セッション B（段階3 カバレッジ）
- 対象: `livelink/src/command_check.cpp`（形の規則と説明の表）、`spec/interface/livelink-protocol.md` の該当の表

## 何が要るか

B は新しいコマンド種別を足さず、既存コマンドの予約欄を variant として使った（定数とコメントは `contract/internal/include/snd/internal/commands.hpp` の末尾）。variant 0 は従来とビット単位で同じ。記録の再生（Replayer）とライブリンクの検査が、次の値を「正しい形」として通し、説明の表にも載せてほしい。

### 組②（D-130, D-132）

| コマンド | 欄 | 値 | 意味 | 検査してほしいこと |
| --- | --- | --- | --- | --- |
| `SetBusVolume` | `reserved` 下位 8 ビット | 1 | バスのエフェクトのパラメータ（`snd_set_effect_param`）。ビット 8〜15 = エフェクト番号、16〜23 = パラメータ番号 | variant 1 のとき `volume` は有限なら**負でもよい**（音量の規則「0 以上」を当てない）。`fadeSeconds` は 0 以上。番号はどちらも 16 未満。ビット 24〜31 は 0 |
| `SetSwitch` | `reserved[0]` | 1 | Event のボイスエフェクトの種別（`snd_set_event_voice_effect`）。スコープ Global、`group` = event id、`value` = エフェクトの種別（0 = 段を外す）、`reserved[1]` = 段、`reserved[2]` = 直後に続く `SetParam` variant 1 の数 | `reserved[1]` < 4、`reserved[2]` ≤ 16 |
| `SetParam` | `reserved[0]` | 1 | ボイスエフェクトのパラメータ。`reserved[1]` = 段、`reserved[2]` = パラメータ番号。スコープ Global なら `param` = event id、Playback なら `target` = 再生 | `reserved[1]` < 4、`reserved[2]` < 16、`value` は有限。スコープは Global か Playback |

知らない variant の値は core が何もせず捨てる（落ちない）。

## それまでの代替

core のテストは `snd::core::System` を直接使うので、規則表を通らない。ライブリンク経由・記録の再生でこれらの関数を使うと、今の規則表の検査で弾かれる可能性がある（未検証）。

### 組④（wip/b-g4、未受け入れ）

`Play` / `PlayOneShot` の flags 上位 16 ビットはフェードインのミリ秒（0〜65535）。従来の下位ビットの検査を保ったまま記録・検査・再生で往復させる。低位の未定義ビットまで一括で許可しないこと。

### 組①・③の作業ブランチで使う値

| 組 | コマンド | 規則表と replay の確認点 |
| --- | --- | --- |
| ① | SetParam variant 2 | Emitter スコープ。reserved[1] は形、value は半寸法 X、param / reserved2 は半寸法 Y / Z の float のビット表現。各軸は有限・非負 |
| ① | SetSwitch variant 2、SetParam variant 3 | 前者は Emitter のゾーン送り先。解除時はバス 0 の 1 命令。設定時は後続の SetParam の value が量（0〜1）、reserved2 がフェード距離の float ビット（有限・非負）。順序を保つ |
| ③ | SetCategoryVolume.reserved = 1 | カテゴリソロ。volume は 0 / 1、fadeSeconds は 0 |
| ③ | ApplySnapshot.reserved = 1 | 対象スナップショットの ACTN 遷移時間。timeSeconds は有限・非負、weight は 0。重みを変更する従来 variant と区別 |

上記は組ごとの受け入れ前。通常の Parameter 名やバス音量としての検査を適用せず、公開 API のエンコードと生記録の往復を照合してほしい。

組①の正式受け入れ `9593633` で、形状のX/Y/Zの割り当て、ゾーン解除1命令、再生時の半寸法をcoreの独立試験で確認した。LiveLinkの規則表を通す往復確認はCへの依頼。
