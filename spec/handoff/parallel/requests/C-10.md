# C-10: パッチのバンクでの表現（PTCH）とランタイムの Patch ソース — セッション D と統合担当あて

依頼元: セッション C 組 M（モデル）。

## 何が要るか

設計書 5・5.1 の Patch（ツールで組む小さな合成グラフ）を、ツールとビルドツールまで作った（`patch` の種類、検査、依存順の配列への変換）。
ランタイムで鳴らすには、次の 2 つが要る。どちらもセッション D の持ち場（`source/`、`dsp/` の新しいファイル）と、バンク形式の `PTCH`（§6.2 で「段階 6 で形式を定める」）。

1. `PTCH` チャンクの形式（minor 版での追加）と、`SYNP.programOffset` / `programBytes` の意味。
2. `SourceKind::Patch` のソース（5.1: 配列を順に処理するインタープリタ、中間バッファはスレッド別アリーナ、モジュレータはブロック単位で評価してサンプル単位で補間）。

## なぜ要るか

ツールのパッチエディタで組んだ音を、ゲームで鳴らすため（11.1、5 章）。今は `XPCH` の中にあり、ランタイムは読まない（鳴らない）。

## 欲しい形（ツール側の仮の定義。D の定義が届けば、それに合わせて変換を差し替える）

- ノードの種類・入力・パラメータの表: `buildtool/include/snd/buildtool/patch.hpp`（`NodeKinds()`、順番がバンクでの種類番号）。
  oscillator / noise / filter / amp / mix / adsr / lfo / random / parameterCurve / envelopeFollower / output。
- 依存順の配列（入力が先、出力ノードが最後）。各ノード: 種類、入力（同じプログラムの中のノード番号）、パラメータ 8 個、
  parameterCurve のパラメータ ID と 8 点まで。仮のバイト配置は bank-format.md §9（`XPCH`）。
- D が別の表（ノードの種類やパラメータの並び）を決めたら、ツールの表（`patch.hpp`）をそれに合わせる。変換は
  `buildtool/src/patch.cpp` の `WritePatchChunk` と `build.cpp` の synth の出力（`kind == 3` の枝）の 2 か所だけ。

## それまでの回避

- バンクへは仮の任意チャンク `XPCH` に出し、`SYNP` は `kind` = Patch、`programOffset` = `programBytes` = 0。
  `PTCH` は書かない。バンクの検証（`bank_check.hpp`）は通る（`buildtool_source_patch_test`、`tool_patch_editor_test`）。
- 既存の「patch は段階 6 まで不可」のビルドエラーは、`synth.patch`（参照）の無い `{"kind": "patch"}` のときだけ残した
  （既存のテスト `build_edge_test` の "patch synth before stage 6" はアサーションを変えずにそのまま通る）。

## つないでいない箇所

- ランタイムでの再生（音が出ない）。ライブでの差し替え（`XPCH` は ReplaceChunk の対象として差分には出るが、ランタイムが読まない）。
- 統合担当へ: `XPCH` を `PTCH` に移すとき、bank-format.md §9 を消し、§6.2 の `PTCH` に定義を書く。
