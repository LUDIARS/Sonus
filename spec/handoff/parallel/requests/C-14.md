# C-14: 音楽の位置の表現の 2 つの穴（拍の中の tick の頭打ち、小節の途中の拍子変化） — 統合担当（契約、music）あて

依頼元: セッション C 受け入れ側（組 M の独立テストで確認）。ツールは回避済み（D-179）。

## 1. 2 分音符・全音符の拍で tick が 959 で頭打ちになる

`snd_musical_time.tick` は 0〜959（`types.h` の注記、4 分音符 = 960）。拍の単位が 2 分音符（beatUnit 2）や全音符（1）の拍子では、
拍の中の位置は 1919（3839）tick まであるが、ランタイム（music の `Timeline`）もツールも 959 で頭打ちにする（3/2 の拍の中 1500 → 959）。
Musical の位置からフレームへ戻すと、拍の後半が同じ位置になる。

- 案: 契約の注記を「拍の中の tick（4 分音符 = 960。拍の単位が長いときは 960 × 4 / beatUnit 未満）」に直し、頭打ちをやめる（1.3）。
- または: この拍子では Musical の位置が近似であることを契約に明記する。

## 2. 小節の途中の拍子変化のあとの小節・拍・tick

設計 8.1 は、拍子の変化点が小節線に無いときの、その後の小節の数え方を決めていない。今のランタイムは小節の位置を連続に扱う
（変化点で端数の小節になる）ので、Musical ⇄ フレームの往復で最大 290 tick ずれる。

- 案: 拍子の変化点は小節線に限る（buildtool が警告またはエラーにする）。または、変化点で小節を数え直すと決める。

## それまでの回避（D-179）

ツールの計算はランタイムの `Timeline` と同じ値にする（比べるテストあり）。Segment のエディタは、小節線に当たらない位置への
拍子の変化を拒否し、読み込んだファイルにすでにあるものは警告として出す。1 の拍子では「Musical の位置は近似」と表示できるようにした。
buildtool の診断は変えていない（既存のプロジェクトのビルド結果を変えないため）。
