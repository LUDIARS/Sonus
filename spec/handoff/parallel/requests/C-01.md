# C-01: core に構造の変更（Config.dev_reserve の範囲）を反映する関数（依頼先: core / セッション B）

## 何が要るか

オーディオスレッドで、ブロック境界に、登録済みのバンクの構造を変える関数。livelink の継ぎ目
`snd::livelink::IStructEditor`（`livelink/include/snd/livelink/struct_edit.hpp`）の実装として使う。

```cpp
// core/include/snd/core/core.hpp（System の live link の節。LiveTap / liveCommand からだけ呼ぶ）
// 予備の行（bank の上書き層が BUSS / EFFX / EVNT に devReserve 行ぶん持っている容量）を有効にして
// 参照表・バスグラフ・派生した状態を組み直す。失敗したら何も変えない。
snd_result LiveAddBus(Id busId, Id parentBus, std::uint32_t channels, float volumeDb) noexcept;
snd_result LiveRemoveBus(Id busId) noexcept;  // 鳴っている入力は親へ / フェードで止める（決めてほしい）
snd_result LiveAddEffect(Id busId, Id effectType, std::uint32_t position, const float* params, std::uint32_t n) noexcept;
snd_result LiveRemoveEffect(Id busId, std::uint32_t index) noexcept;  // テールの扱いは 2.4 の作法
snd_result LiveAddSend(Id fromBus, Id toBus, float levelDb, bool preFader) noexcept;
// 予備の残り（行、spare バイト）。livelink の数えとの突き合わせ用。
void LiveReserveLeft(std::uint32_t* buses, std::uint32_t* effects, std::uint32_t* events, std::uint64_t* bytes) const noexcept;
```

## なぜ要るか

設計書 11.2「バスやエフェクトの追加など構造の変更は、開発用の予備容量の範囲で受け付け」。bank の上書き層には予備の行
（`DevOverlay::reserveBuses` など）があるが、core の `LiveWriteCell` は `row < rows` しか書けず、バスグラフや
エフェクトのインスタンス（DSP プール）を組み直す手段が無い。livelink だけでは実現できない。

## それまでの回避

livelink は検査・予備容量の数え・記録・Ack・セッション・切断時の戻しまで作り、最後の一歩を `IStructEditor` に渡す。
既定（編集器なし）は SND_ERR_UNSUPPORTED を返し、ツールは再ビルドとホットリロード（ReloadBank）に回る。
テストは偽の編集器（`livelink/test/livelink_v11_common.hpp` の `FakeEditor`）で通している。

## つないでいない箇所

- `RuntimeDesc::structEditor` に渡す本物の編集器（上の関数を呼ぶ薄い実装）。構成ルート（`api/compose/compose.cpp`）で
  `LiveRuntime::Create` に渡す配線も要る（api の行の変更なので、統合のときに）。
- `Config.dev_reserve.events`（イベントを足す op が無い）。
