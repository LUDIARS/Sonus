# C-03: 継ぎ目のないホットリロードと、バイト列からのバンクの読み込み（依頼先: bank / core、api）

## 何が要るか

1. 同じ（bankId, languageId）のバンクを、古い写しを登録したまま新しい写しを読み込み、ブロック境界で参照を差し替え、
   鳴っている音を新しい写しへ移す（または古い写しの音を最後まで鳴らす）登録の形。古い写しはエポックで解放する。
   例: `BankManager::LoadReplacement(HandleRef old, const char* path)` と `cmd::BankRegister` の variant「置き換え」。
2. ゲームのファイルシステムを通さずにバイト列からバンクを読む入口（ツールが再ビルドしたバンクを分割して送るため）。
   例: `System::LoadBankFromMemory(const void* image, std::uint64_t bytes, void (*release)(void*), void* user)`。

## なぜ要るか

設計書 11.2「波形の差し替え等は通常の読み込み経路で新しい領域に読み、参照を差し替えたあと古い領域をエポックで解放する」。
今の bank は同じバンクが 2 つ登録されることを許さず（D-50、古い写しの解放を待つ）、core の `UnloadBank(STOP_AND_UNLOAD)`
はそのバンクの音を止める。ゲームの機械にファイルが無い（コンソールの開発機など）とパスでは読めない。

## それまでの回避

`ReloadBank`（livelink-protocol.md §8.5）は「外して止める → 同じ経路で読み込む → 古い写しの解放を待って登録」。
そのバンクの音は短いフェードで止まる（決めた振る舞い）。パスはゲームのファイルシステムの根からの相対（D-103）。

## つないでいない箇所

鳴ったままの差し替え、バイト列の転送（プロトコルのメッセージも、1 の手段ができてから足す）。
