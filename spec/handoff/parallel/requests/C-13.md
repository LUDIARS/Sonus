# C-13: カーブの合成が設計 4.3 とランタイムで食い違う — セッション B（core）と統合担当あて

依頼元: セッション C 受け入れ側（組 M の独立テストで確認）。ツールは回避済み（D-179）。

## 何が食い違うか

設計 4.3 は、複数のカーブが同じ対象に効くとき「音量とピッチは加算、ローパスは最小、ハイパスは最大、その他は乗算」とし、
カーブごとの `compose` で変えられるとしている。今のランタイム（`core/src/sys_dsp.cpp`）は次のとおり。

- パンは**加算**（4.3 では「その他」＝乗算）。
- バンクの `CURV.compose` 列を**読まない**（対象ごとに固定の規則）。プロジェクトに `compose` を書いても音は変わらない。
- パラメータの `scopeMask`（宣言したスコープ）を確かめない。宣言の外のスコープに設定した値も使われる。
- 対象 send / effectParam / spread / reverbSend / blend3D はランタイムが未対応（段階 3 の残り）。

## 決めてほしいこと

どちらかに揃える。

- (a) 4.3 を今のランタイムに合わせる（「パンは加算」、`compose` は固定の規則の対象では無効）。
- (b) ランタイムが `compose` を読み、4.3 のとおりにする。スコープの宣言も確かめる。

## それまでの回避（D-179）

ツールの計算は今のランタイムと同じ値にする（11 章「ツールで聞いた音とゲームで鳴る音を一致」）。ランタイムが読まない `compose` は
エディタが `ComposeIgnored` として警告し、宣言の外のスコープの値は `outsideScope` として報告する。未対応の対象は `compose`
（既定は乗算）で計算して見せるだけ。`tool/test/runtime_compare_test.cpp` が本物の core の出力と比べているので、ランタイムを
(b) に直すとこのテストが落ちる。そのときはツールの計算（`tool/src/curve_editor.cpp`）を合わせる。
