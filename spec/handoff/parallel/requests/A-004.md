# A-004: Emitter を同じまとまりで作成・移動・破棄すると位置が効かない／PlayAt の暗黙の Emitter（core への依頼）

- 依頼元: セッション A（physics）
- 宛先: core の所有者（`core/src/sys_apply.cpp`、`core/src/sys_3d.cpp`）
- 状態: 未着手。physics は回避策（Emitter を `emitter_hold_seconds` のあいだ保持）で動いている。

## 1. 欠陥: 「再生は最後の transform を保つ」が成り立たない場合がある

`sonus.h` の `snd_destroy_emitter` のコメントは「Playbacks on the emitter keep the last transform」。
ところが、同じフレーム（同じ ApplyCommands）で

```
e = snd_create_emitter(sys);
snd_set_transform(sys, e, &(snd_vec3){2, 0, 0}, NULL, NULL);
snd_play(sys, event3D, e, NULL);
snd_destroy_emitter(sys, e);
snd_update(sys);
```

とすると、再生はリスナーの位置（中央、距離減衰なし）で鳴る。

確かめた結果（`SND_OUTPUT_MANUAL`、DC 0.5 のモノラル素材、3D の Event、リスナーは原点で前 (0,0,1)・上 (0,1,0)、
Emitter は右 2 m。期待は L ≈ 0、R ≈ 0.25）:

| 手順 | L | R |
| --- | --- | --- |
| 作成・移動・再生（破棄しない） | 0.000 | 0.250 |
| 作成・移動・再生・破棄を同じフレーム | 0.354 | 0.354（中央・減衰なし） |
| 作成・移動の後に 1 周期進めてから、再生・破棄 | 0.000 | 0.250 |
| `snd_play_at`（右 2 m） | 0.000 | 0.250 |

原因（読んだ範囲）: `Compute3D`（`sys_3d.cpp`）は生きている Emitter の行についてだけ `Spatial` を計算する。
`DestroyEmitter` は ApplyCommands の中で行を消すので、そのブロックで作られた Emitter は一度も `Spatial` が
計算されず、ボイスは無効な 3D 値（2D 扱い）で鳴る。前のブロックで計算済みなら、その値が残るので正しく鳴る。

直し方の案:
- `DestroyEmitter` で、その Emitter を参照する Playback があれば、行を消す前にその Emitter の `Spatial` を計算する
  （`Compute3D` の 1 行分を呼ぶ）。または
- 破棄を「そのブロックの Compute3D の後」にずらす（破棄のビットを立てて、Compute3D の後に消す）。

## 2. 振る舞いの確認: `snd_play_at` の暗黙の Emitter は利用者の Emitter と同じプールから取る

`CreatePlayback`（`sys_apply.cpp`）は `kPlayHasPosition` のとき `im.emitterSlots.Acquire()` で暗黙の Emitter を取る。
`max_emitters` を使い切っていると、位置なし（リスナーの位置）で鳴り、何も通知されない。physics は「Emitter が取れないとき
`snd_play_at` に落とす」ので、そのときは位置が効かない。

依頼: どちらかにしてほしい。
- 暗黙の Emitter 用の予備（`Config` の容量）を持つ。
- 取れなかったことを `on_error`（警告）か終了理由の detail で知らせ、`sonus.h` のコメントに書く。

## 3. physics 側の対応

1 が直ったら、`emitter_hold_seconds` の既定を 0（次の呼び出しで破棄）にできる。A-002 が入れば保持そのものをやめる。
