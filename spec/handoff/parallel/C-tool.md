# セッション C: 段階5 ツールの完成（全画面、記録と再生）

始める前に、共通の決まり `spec/handoff/parallel/README.md` を読み、そのとおりに進める。

- ブランチ: `int/s7-tool`（`int/s2-integration` から作る）
- 持ち場: `tool/`、`livelink/`、`buildtool/`
- 決定番号: D-170〜D-189

## 1. 目的

設計書 11 章のオーサリングツールを完成させる。今あるのは、ミキサー、プロファイラ、上書き、録画（D-67、D-100〜D-101）だけ。

- UI は **LUDIARS Tela** を使う（D-67）。Dear ImGui と Qt は使わない。
- ツールの核（`Sonus::tool_core`）は、UI に依存しないまま保つ。
  - 新しい画面の中身（モデル）は、すべて核の側に置く。
  - Tela に依存するのは `tool/ui/` と `tool/app/` だけにする。
  - こうしておくと、Ergo Studio の sonus プラグイン（LUDIARS/Ergo）が同じモデルを使える。

## 2. 作るもの（11.1 の全画面）

画面ごとに、核の側のモデルと、Tela の画面の両方を作る。

- **Event エディタ**
  - トラックとクリップのタイムライン
  - シーケンス種別
  - ランダム幅
  - アクション
- **ミキサーの残り**
  - センド
  - エフェクト
  - スナップショット
  - ダッキング
  - カテゴリ
- **パラメータとカーブのエディタ**
  - スコープ
  - 追従速度
  - 合成の規則の確認
- **3D 減衰のプレビュー**
  - 上から見た図
  - リスナーとエミッタを動かして試聴する
- **音楽エディタ**
  - テンポ、拍子、マーカー
  - Playlist、Stem、State
  - 遷移ルール表
  - 遷移の試聴
  - 最小先読み時間の表示
- **マテリアル表エディタ**
  - 単体音
  - 組の上書き
  - 代替の一覧
  - 強さのカーブ
- **波形生成パッチエディタ**
- **プロファイラの残り**
  - CPU
  - メモリの区分
  - ストリーム
  - 負荷 LOD の段
  - イベントログ
- **記録と再生（11.3）**
  - コマンド列（適用ブロックの番号付き）
  - 負荷 LOD の変化
  - ストールの記録
  - ツールで再生すると、2.5 の範囲で同じ結果になること
  - 不具合報告とテストにも使えること
- **ライブ接続（11.2）の残り**
  - 接続時の照合（プロトコルの版、ビルドハッシュ）と、不一致のときの選択（差分をすべて送る／拒否する）
  - オブジェクトの差し替え（再ビルドしたチャンクを送る）
  - 試聴再生
  - 開発用の予備容量（`Config.devReserve`）の範囲での構造の変更
  - 大きな差し替えのホットリロード（エポックで解放する）
- **持ち越しの livelink 候補**（`spec/handoff/hq-handover.md` 4 章、CONTRACTS.md の見送りの節）
  - 項目単位の Revert のコマンド
  - セルの現在値の読み返し（LiveReadCell）
  - Client のストリームの更新番号
  - BlockTiming.budgetMicroseconds の定義

## 3. 並行するセッションとの関係

- B（core / dsp）、A（physics）、D（拡張）がランタイムの機能を足していく。
- C の画面は、すでに統合されているランタイム（`int/s2-integration`）にある機能に対して作る。
- まだランタイムに無い機能の画面は、次のように作る。
  - モデルとプロジェクト形式（`spec/interface/project-format.md`）、buildtool の出力までを作る。
  - ライブでの反映は、その機能が統合されたあとにつなぐ。
  - つないでいない箇所は報告に一覧で書く。
- 例: マテリアル表は A、波形生成パッチは D、標準 DSP の各エフェクトは B に当たる。
- **ライブリンクのプロトコル**は、版の付いた凍結の契約（`spec/interface/livelink-protocol.md`）。追加（新しいメッセージ）だけ許す。livelink-protocol.md の互換性の節のとおりに版を上げ、自分の節に記録する。
- **Tela に要る変更**は、`hq-handover.md` 3 章の 9 件を含め、Tela 側の課題として報告に書く。Tela のリポジトリには手を入れない。足りないところは、ツールの中で回避する。

## 4. テスト

- 画面のモデル: 核の側のテストに置く（Tela は不要）。
  - 編集
  - Undo と Redo
  - 保存と読み込みで、内容が元に戻ること
  - buildtool の出力
- 画面: 既存の `tool/test` の流儀に従う（CPU の compositor で描いて、画像を比べる、または要素の木を確かめる）。
- 記録と再生: 同じ記録を 2 回再生して、決定が一致し、2.5 の条件ではビットも一致すること。
- ライブ接続: 照合の不一致、差し替え、ホットリロード、予備容量の超過を確かめる。
- ファズ（14 章）: 壊れたライブリンクのメッセージを入れても落ちないこと。
