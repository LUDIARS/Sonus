## 作るもの（全部。配線と自分のテストまで）

設計書 4.5 と 7 章の「3D基本」「距離カーブ」「範囲・空間構造」の行を、設定意図どおりに動く形にする。ルーム／ポータルは作らない（段階6、セッション D）。

### 1. ドップラー（D-150）
- `Spatial.dopplerRatio` を Compute3D で計算する（列と読み出し宣言は既にある）。比 = (c − vL·n) / (c − vS·n)（n はリスナーから音源への向き…符号は「近づくと高くなる」になるように。式と符号をコメントに書く）。速度は Listener / Emitter の速度の列。
- `snd_config` の末尾に全体値を足す: `doppler_factor`（既定 1.0、0 で無効 = 比が厳密に 1）と `speed_of_sound`（既定 343.0 m/s）。範囲は自分で決めてヘッダに書く。
- 比は安全な範囲に頭打ち（マッハ 1 付近で発散しない。上限・下限をヘッダに書く）。Voice のピッチに掛け、`maxPitchRatio` の頭打ちは既存どおり。
- 位置が外挿・補間されるのと同じく、ブロック間で階段にならない（既存のピッチのランプに乗せる）。
- `doppler_factor = 0` と、速度 0 のときは、従来とビット単位で同じ出力。

### 2. 距離減衰とロールオフ（D-151）
- 既存: `EVNT.curveVolume` があればそのカーブ、無ければ 1/max(d,1)、`maxDistance` で 0。これは変えない（既存テスト `Core3D.DistanceAndDirection`）。
- 足すもの: 距離カーブ（音量・LP・spread・3D ブレンド）が設定どおりに効くことのテスト。距離を入力にした Parameter カーブ（`CURV.input = kInputDistance`）の HP も。
- 既定ロールオフの種類（線形・対数・最小距離）を選ぶ列は無い。**足さない**（距離カーブで表現できる）。報告に「依頼になるもの」として、要るかどうかの意見を書く。

### 3. コーン・spread・2D/3D ブレンド（D-152）
- コーン: 既存の実装（内角・外角・外側 dB）を確かめ、足りない所を直す。コーンの外側の LP は列が無いので作らない（依頼の材料に書く）。
- spread: カーブ以外の一定値は列が無い。範囲音源（下の 5）の内側での spread は作る。
- 2D/3D ブレンド: いまパンだけに掛かり、減衰には掛からない。**ブレンド 0（完全 2D）なら距離減衰・コーン・ドップラー・距離 LP も効かない**、中間は 2D と 3D の線形の混ぜ（ゲインは線形、ピッチ比とカットオフは対数で補間）とする。ブレンドのカーブが無い Event は従来どおり（ビット一致）。

### 4. 複数リスナー（D-153）
- `Config.listener_mode` を実際に読む。
  - 最寄り（既定、従来どおり・ビット一致）。
  - 重み付き: リスナーごとに距離・向きを計算し、`Listener.weight` で合成する。
  - 画面分割（Split）: リスナーごとに空間化した結果を同じ出力に足す。
- 満たすこと（合成の式は自分で決めて提案に書く）:
  - リスナーが 1 人のときは 3 方式ともビット単位で同じ。
  - 同じ位置・向きの 2 人のリスナーは、1 人のときと同じ音量（倍にならない）。
  - どの方式でも、音量は「いちばん大きく聞こえるリスナー 1 人だけのとき」を超えない。
  - ドップラーと距離 LP は、いちばん寄与の大きいリスナーのものを使う（重み付き・Split とも）。入れ替わりでクリックを出さない（ブロック内ランプ）。
  - 計算は Emitter × Listener の組ごとに 1 回（設計 4.5）。リスナー数の上限は Config の既存の値。
- Split を物理的に別の出力に分けるのは platform / api の話なので作らない（依頼の材料に書く）。

### 5. 遮蔽・閉塞（D-154）
- `snd.occlusion` / `snd.obstruction`（Emitter スコープの Parameter、0..1）は `Emitter.occlusion` 列まで来ている。これを音に効かせる。
  - 遮蔽（occlusion）: 直接音と送り（リバーブ送り・ゾーン送り）の両方に、音量の低下と LP。
  - 閉塞（obstruction）: 直接音だけに音量の低下と LP。送りには掛けない。
  - 写像: 0 で従来とビット一致。1 で最大（音量 dB とカットオフの値は自分で決めて提案に書く。`snd_config` 末尾の tuning に置けるなら置く）。LP は既存の「最小値を取る」合成に乗せる。
- 値の変化は Parameter の追従速度とブロック内ランプで滑らか。

### 6. 範囲音源（D-155）
- 形: 点（既定）、線、面（矩形）、箱。Emitter の位置・向きを中心と軸にする。
- 公開関数 `snd_set_emitter_shape(sys, emitter, kind, const snd_vec3* half_extents)` を足す（スカラーと既存の型だけ。sonus.h / sonus.hpp / c_api.cpp の末尾）。形の種類は types.h の列挙の追加で。
- コマンドは新しい種別を足さない: `SetParam`（Emitter スコープ）の `reserved[0]` = 2 を variant にして運ぶ（3 は予備。どの欄に何を入れたかを commands.hpp の末尾に定数とコメントで書く）。複数コマンドになるなら全部入るか 1 つも入らないか（組②の `System::SetEventVoiceEffect` の `ArenaFits` の形）。
- スキーマ: Emitter の形の列と読み出し宣言を足す（1 列 1 書き手）。
- 振る舞い: 距離と方向は、形の上でリスナーにいちばん近い点で計算する。リスナーが形の内側（箱）・形の上にいるときは距離 0 扱いで、spread が広がって定位が消える（内側で全方向、形から離れるほど点に近づく。式は提案に書く）。
- Emitter が動く・回るときも滑らか（最近点の飛びでクリックを出さない）。

### 7. リバーブへの送り（距離カーブ）とリバーブゾーン（D-156, D-157）
- **ボイスからの補助送り**を作る: ボイスは今 1 つのバスにしか出ない。もう 1 本、送り先バスへ量付きで足せるようにする（D-43 の規則どおり、チャンクのアキュムレータに区分を足す形。直列と並列でビット一致）。送りはボイスのフェーダー・ボイスエフェクトの後、パン行列を通した形で足す（提案に書く）。
- D-156 距離カーブのリバーブ送り: `EVNT.curveReverbSend`（既存の列。いまは読まれない）を読む。送り先は「Event のバスの最初の SEND 行の先」とする（列を足せないため。バスに SEND が無ければ送らない）。Event 専用の送り先の列は依頼の材料に書く。
- D-157 リバーブゾーン: ゾーン = 形を持つ Emitter（6 の形）+ 送り先バス + 量 + フェード距離。
  - 公開関数 `snd_set_reverb_zone(sys, emitter, bus, amount, fade_distance)`（bus = `SND_ID_NONE` で解除）。コマンドは `SetSwitch`（Emitter スコープ、`reserved[0]` = 2）で送り先バス、`SetParam` variant で量とフェード距離（形と同じく全部か無しか）。
  - 効き方: **リスナー**がゾーンの内側なら量 1 倍、外側はフェード距離で 0 まで線形に落ちる（Unity の Reverb Zone と同じ向き）。その重み × 量を、3D の全ボイスの補助送り（送り先 = ゾーンのバス）に足す。複数のゾーンが重なるときは、重みの大きい順に上限 N 個（N は `snd_config` 末尾か定数。提案に書く）まで、それぞれのバスへ送る。
  - 距離カーブの送り（D-156）とゾーンの送りが同じバスなら量は加算（上限 1）。
  - ゾーンの数の上限は Emitter の上限に含まれる。ゾーンの Emitter で再生しても普通の音源として鳴る（ゾーンは属性）。
- 補助送りを持つボイスが仮想になったら送りも止まる（描画しないので）。

### 8. 空間化プラグインへの 3D 情報
- `snd_render_context` に欄が無い。**契約の構造体は変えない**。報告の「依頼になるもの」に、要る欄（方位・仰角・距離・spread）を書くだけ。

## 守ること（共通の決まりに加えて）
- 既存の出力をビット単位で変えない: 新しい設定が全部既定値（ドップラー係数だけは下を見る）なら、既存のテストとゴールデンがそのまま通ること。
  - `doppler_factor` の既定 1.0 は、速度を持つ Emitter / Listener の既存のテストの出力を変えうる。既存のテストが落ちたら**アサーションは書き換えず**、どのテストがどう落ちたかを報告する（受け入れ側が既定値を 0 にするか決める）。先に `grep` で速度を渡している既存テストを調べ、報告に書く。
- `snd_config` に項目を足すと、api の `config_check` が大きさで弾く可能性がある（組②で同じ事が起きている。`contract/public/include/snd/config.h` の末尾の X マクロと `api/` の検査を読む）。api は持ち場の外なので変えず、core のテストは `snd::core::System` を直接使う。報告の「依頼になるもの」に書く。
- 3D の計算は Emitter × Listener の組ごと（Spatial 表）。ボイスごとに三角関数を増やさない。性能: Release で `CoreLoad.Real128VoicesWithinBudget` が通り、128 本の 3D ボイス（全部が動く Emitter、ドップラーあり、補助送りあり、ゾーン 4 個、リスナー 2 人の Split）の負荷テストを足して、1 ブロックの時間と予算比（30 % 未満）を報告する。
- 決定論（直列 2 回と RT ワーカー 2 でビット一致。`tuning.lod_down_blocks = 0`、遅れチャンクなしの条件）、初期化後の確保 0、RT 違反 0 を、新しい経路を全部通る台本で確かめるテストを足す。
- 自分のテストは `core/test/core_g1_*_test.cpp`（新しいファイル。CMake は末尾追記）。機能ごとに、設定意図どおりの数値（距離 → ゲイン、速度 → 周波数、角度 → ゲイン、内側 → spread、ゾーン内外 → 送り先バスのレベル）を見る。
