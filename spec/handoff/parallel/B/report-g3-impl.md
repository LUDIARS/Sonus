# 組③ 実装担当の復元記録

公開先頭 `700b4fd` に統合先 `c86901f` を取り込み、旧環境の未公開コミットを参照できない状態から復元した。下表のテスト名はこの作業ツリーにあるケース。旧環境の性能や合格件数は転記していない。

| 判断候補 | 実装と検査 |
| --- | --- |
| D-160 | SetParamValue で定義済み PARM の不許可スコープを取り除き、ParamValueOf は現在のマスクで Playback → Emitter → Global → 既定の順に読む。未定義 ID とマスク省略は従来どおり3スコープ。追従は共有する行ごとに既存の Step が1ブロックに1回行う。CoreG3.ForbiddenScopeKeepsAllowedValue。 |
| D-161 | 音量は dB 加算、ピッチは cents 加算、LP は最小、HP は最大。Pan の乗算指定は複数寄与を積にしてクリップ値に加える。旧パンはクリップ値から行ごとに加算する。独立試験 IndepG3Param.LegacyPanAddsCurvesToClipInStoredOrder。 |
| D-162 | Spread、Blend3D、ReverbSend の寄与を声ごとに保持。指定したカーブの積を距離評価後に掛ける。距離カーブを省略して Parameter カーブだけを指定したときの積の始点は1。組①のリスナー別評価と送りには統合時に接続する。 |
| D-163 / 164 | SNPV の重みをバス・送りでは dB、FX ではネイティブ単位に掛ける。FX は D-130 の制御値に加算し、最終値に範囲制限を適用。初期化時のみの値には加算しない。共有バンクでは元の行をバスIDとチェーン内位置で実体へ移し、FX種別、あるいは送り先と pre/post の一致を必要とする。送りはブロック内で前回値から補間。CoreG3.WeightedMixReplaysBitExactly。 |
| D-165 | ApplySnapshot の reserved=1 は今後の当該スナップショットアクションの遷移時間を設定する。再指定は直前の重みから開始する。親の初期発火を仮適用する処理は組④にあり、統合時に親の受理・拒否を確認する。 |
| D-166 | 前ブロックのフェーダー後ピークがしきい値を超える dB を amountDb の絶対値で制限して減衰。既存の指数型 attack/release を使う。キーの初フレームはバスの世代で確認する。ルール型はカテゴリ内の発音数が正の間働く。 |

公開関数は snd_set_category_solo と snd_set_snapshot_action_transition。C++ ラッパーおよび core の同名操作、core の SetFocusLost(bool) を追加した。予約フィールドは SetCategoryVolume.reserved=1 と ApplySnapshot.reserved=1。追加のコマンド種別、設定フィールド、スキーマ列は使用していない。

B-1 は新 variant のライブリンク記録再生、B-2 は Send／EffectParam の宛先列と ACTN 遷移時間、B-3 はフォーカス通知から core への接続および C API の一巡を担当する。

## 試験状況

`825cf18` 時点で組③のセルフ試験5ケースと独立試験を作業ブランチに収録した。セルフの複合台本はパラメータ、多重スナップショット値、プリ送り、ダッキング2方式、ソロを同時に有効にし、直列2回／RTワーカー2、確保、RT違反、128実声のCPUを検査する。構成別の実行結果は排他ビルドの完了後に追記する。

GCC 14 Debug の担当側新規ビルドは `2197e17`。core_g3_mix_test は5/5成功、ビルド警告0。20声の複合台本の出力は直列2回とワーカー2でバイト一致し、同じ台本と128声台本はいずれもセットアップ後の Sonus アロケータ確保0・RT検出0。128実声の Debug 計測は直列6384.5 µs（119.7%）、ワーカー2で6131.3 µs（115.0%）。予算5333.3 µsに対する合否は Release の実測で判定する。

`7da170a` の新規 GCC 14 Release でセルフ5/5、警告0。128実声・1ブロックのCPU時間は直列312.6 µs（5.9%）、RTワーカー2で466.3 µs（8.7%）。予算は5333.3 µs。

D-161 は設計4.3の対象別規則を優先する。Pan の Multiply は列に値4が存在するときに適用し、列を省略したときの読み値0と明示された加算はいずれも旧順で加算する。B-2 に記載のとおり、writer は全行が既定値の任意列を省略するため、作者が明示した全行0と既存の省略バンクをバイナリ上で区別できない。音量の乗算など、対象別規則とは異なる組み合わせに新しい動作を割り当てていない。

組③実装側の一時統合試作 `9a1538e` で、GCC 14 Debug の indep_g3_control_test は7/7、indep_b_cross_test は5/5成功。初期アクションの親が受理された場合は開始時計・指定時の遷移時間を維持し、拒否時は先行遷移に戻った。空間化の3ターゲットは距離カーブの有無を変えて左右波形を照合した。横断台本で直列2回とRTワーカー2の音声・通知・スペクトルが一致し、128実声・4FXの確保0・RT違反0。CPU時間は直列1218.04 µs、ワーカー2で3594.06 µs（Debug）。正式な受け入れは各組の統合先取り込み後に行う。

`bc49fbe` の Clang 19 Debug はセルフ5件と独立25件を含む3登録すべて成功し、コンパイル警告0。GCC 14 Release でこの3登録をそれぞれ20回反復し、60/60回成功した。

`80a72f7` で長時間のアクション遷移を追試した。131072 Hz × 32768 秒は 2³² フレームに達するので、FadeFrames は uint32_t の最大フレーム数に飽和させる。CoreG3.LongSnapshotActionAtHighSampleRateKeepsFading で即時指定と長時間指定の出力を比較した。セルフ6件＋独立25件の3登録は Clang 19 Debug、ASan/UBSan（detect_leaks=0）、GCC Release・TSan 各20回が成功した。警告0。MinGW は単独の19ファイル、組①・④を使う横断用の2翻訳単位も検査を通過した。

`80a72f7` と①④の結合候補 `82a5c3d` を合わせた。EvaluateDspParams の各リスナーで Spread・ReverbSend・Blend3D を距離曲線と掛け合わせる。ApplyDueActions、ApplyFirstBlockActions で親の初回アクションに開始時計・遷移時間・スナップショット世代を記録し、CommitTentativeSnapshots と EvaluateDspParams が同じ遷移を使う。拒否・取消時は先行していた重みを保つ。旧 Pan は格納順でクリップ値から加算し、共有バスの送り・FX 寄与とキーバスの世代照合も引き継いだ。同じレンダー・ミックス実装を持つ試作 `0fce174` の GCC Debug では、組②容量、組③セルフ・ミックス・制御、横断の計5登録が成功した。正式候補の実測は受け入れ側で行う。
