## 2. 誰が何を書き、どう取り込むか

- 各組の**実装担当と独立テスト担当は別のセッション**にする。独立担当は実装を読む前に仕様と公開ヘッダから検査すべき性質を書き出す。受け入れ担当は実装もテストも書かず、担当作成のコミットを内容そのままで作業ブランチにpushする。
- 各組は統合先の先頭を取り込み、独立試験の `Defect_` が0になるまで決定・差し戻し・再確認を行う。受け入れ担当が直しの差分を読み、新規ビルドで条件を満たしてから、**②の直し → ④ → ① → ③** の順で `git merge --no-ff` し、pushする。各組の区切りで決定・依頼・分類表・報告も更新する。①と③の実装・独立試験は並行してよい。重いコマンドの実行は§3に従う。
- 本社は `core_voice_test.cpp:149` と、`c377047` 基準の `core_voice2_test.cpp` の57・76・90・107・115・157・158行を承認済み。テスト担当が変更し、終了理由の実装変更と同じコミットに含める。旧環境では157・158も実際にグループに奪われ、全7箇所で `SND_END_STOLEN / SND_END_DETAIL_LIMIT_GROUP` を観測した。復元時も経路を確認し、全体上限なら詳細を `VOICE_LIMIT` として記録する。`REJECTED` と `CountOf(...) == 0` の既存期待は保持する。同じ原因の別の既存期待だけは同じ扱いで修正できる。詳細は [B-6](requests/B-6.md) を参照。
- コードの変更範囲は `core/`、`dsp/`、`api/compose/c_api.cpp` の末尾、`contract/` への追加。コマンド種別追加・契約版更新・凍結ファイル変更は不可。受け入れ担当は末尾追記の両立・重複宣言1行化だけを解決し、意味の判断を伴う衝突は実装担当に戻す。
- push先は `int/s7-coverage` と `wip/b-g1`〜`wip/b-g4` だけ。日本語でこまめにコミットしてpushする。PR・force push・他セッションの取り込みは行わない。

## 3. 受け入れと例外の判定

- B-handoff §3の7構成はGCC Debug、Clang Debug、ASan/UBSan、TSan、Release、テストなしRelease、Opusなし。DSPに触った組と最終統合はscalarとAVX2/FMAを加える。旧組④の性能修正は `dsp/src/resampler.cpp` にあるので、復元したら組④も9構成。警告0、変更テストはRelease・TSan各20回、変更ファイルはMinGW構文検査。ビルドは `-j2`、重いコマンドは一つずつ `flock /tmp/snd-heavy.lock <コマンド>`。TSanのctestは `-j1`。
- 性能失敗は同じ実行ファイルだけを他のビルド・テストと重ならないよう `-j1` で5回。各値を報告し、中央値が予算の30%未満なら通過、30%以上なら差し戻す。前回の組④では128実声・メーター付き8バスとスペクトルで、担当のRTワーカー2本の中央値が33.2%。Sinc位相の係数差を事前計算した後は20.7%。受け入れ担当による修正後の旧新照合と全構成は未完了。
- 順序・タイミング依存は20回繰り返し、1回でも再現すれば欠陥。再現しなければ失敗時の出力を報告する。担当外なら依頼を書く。LeakSanitizerが起動不能なら `ASAN_OPTIONS=detect_leaks=0` でASan/UBSanを回し、リークは未検証とする。他の環境起因の失敗は3回試し、コマンドと出力を残す。コードの失敗は差し戻す。
- `SpecHole_` は新設定が既定値のとき旧出力がビット一致する案を選ぶ。なお決まらなければ現行動作を仕様としてD番号を付ける。承認対象外の既存期待と設計が食い違えば既存期待に合わせ、担当外の必要変更とともに `requests/B-*.md` に記録する。同じ欠陥の差し戻しが3回続けば、落ちる `Defect_` と記録を残し、その組のマージを保留して他組を進める。
- 自動審査に拒まれた操作は言い換えて繰り返さない。通常のgit pushなど正規の別手段を一つ試し、失敗すればローカルコミットを残して他の作業を続ける。環境が落ちれば最後の公開チェックポイントから再開する。
- 本社への再確認が必要なのは、禁止されたpush先・force push・PRが必要な場合、承認外の既存期待変更が不可避な場合、契約版・コマンド種別・凍結ファイル（`tests/framework/`、`tests/mocks/`、ルート `CMakeLists.txt`、`cmake/`）の変更が不可避な場合、またはpush不能で4組ともローカルで進める作業が尽きた場合。停止時には必要なもの、選択肢、推奨案を一度に報告する。
